# 従業員ポータル（目標自己採点・アンケート・提案）設計書

作成日: 2026-09-23

## 背景・目的

天理店の従業員向けに、以下3つの機能を1つのWebシステムにまとめて提供する。

1. 従業員個々に設定された目標に対する自己採点の集計
2. アンケート（匿名・記名、店長が自由に作成）
3. 提案（記名・匿名で従業員が自由記述を投稿）

対象は天理店のみ。既存のPOSダッシュボード（`売上管理\pos_system\dashboard.py`）とは別アプリとして
新設するが、認証方式やクラウドDB（Supabase）は既存の仕組みを踏襲・共用する。

## 全体アーキテクチャ

```
[従業員のスマホ/PC] --HTTPS--> [Flask Webアプリ (Render 無料枠)] --> [Supabase (PostgreSQL, 新規テーブル群)]
```

- **フレームワーク**: Flask
- **ホスティング**: Renderの無料Webサービス枠。GitHubリポジトリと連携し、`git push`で自動デプロイ
- **DB**: 既存Supabaseプロジェクトに新規テーブルを追加する（POSの`sales`等とは完全に別テーブル。
  `employee_`プレフィックスで区別）
- **配置場所**: リポジトリ内に新規フォルダー `スタッフ管理/employee_portal/` を作成
- **認証**: POSダッシュボードと同じ「共通パスワード（一般）＋管理者パスワード（店長）」方式。
  ログイン後、一般は従業員用画面、店長（管理者）は管理画面に入る
- **設定管理**: `config.json`にSupabase接続情報・パスワードを集約し、Gitには含めない（`.gitignore`登録）

## データモデル（Supabase新規テーブル）

```
employees                従業員マスタ（店長がアプリ内で登録・編集）
 ├─ id, name, is_active, created_at

goals                    目標（店長が従業員ごとに登録）
 ├─ id, employee_id(FK), goal_text, created_at

goal_scores              自己採点（1目標に対し複数回・都度記録。頻度は自由）
 ├─ id, goal_id(FK), score(1-5), comment, scored_at

surveys                  アンケート（店長が作成）
 ├─ id, title, is_anonymous(bool), created_at

survey_questions         アンケートの質問
 ├─ id, survey_id(FK), question_text, question_type(free/choice), choices(JSON), sort_order

survey_responses         回答（1人1回答。匿名時はemployee_idをNULLのまま保存）
 ├─ id, survey_id(FK), employee_id(FK, NULL可), submitted_at

survey_answers           個々の設問への回答
 ├─ id, response_id(FK), question_id(FK), answer_text

proposals                提案（匿名時はemployee_idをNULL）
 ├─ id, employee_id(FK, NULL可), content, status(未対応/対応中/完了), created_at
```

- 自己採点は「頻度自由」の方針に合わせ、`scored_at`を持つ時系列データとして保存する
  （採点回数・頻度をあとから自由に変えられる。グラフで推移も表示できる）。
- 匿名（アンケート・提案）は`employee_id`をNULLのまま保存し、IPアドレスやセッション情報など
  個人特定につながる情報は一切記録しない。

## 画面・機能フロー

### ログイン
- 共通パスワード → 従業員メニュー / 管理者パスワード → 店長メニュー
- 従業員メニューに入る際、自己採点など記名が必要な機能のために「あなたの名前」をプルダウンで選択し
  セッションに保持する

### ① 目標自己採点
- 店長画面: 従業員を選んで目標を登録・編集（複数可、完了した目標は非表示化できる）
- 従業員画面: 自分の名前を選択済みの状態で、自分に登録された目標一覧が表示される。
  各目標に対し5段階評価＋コメントを入力して記録する（何度でも追記可能）
- 店長画面: 従業員別・目標別の採点推移をグラフ・一覧で確認する

### ② アンケート
- 店長画面: 「新規アンケート作成」でタイトル・匿名/記名を選択し、質問（自由記述 or 選択式）を
  追加して公開する
- 従業員画面: 公開中のアンケート一覧から回答する。匿名アンケートでは名前選択欄自体を表示しない
- 店長画面: 回答一覧・集計を確認する（選択式は件数集計、自由記述は一覧表示）。匿名回答は
  誰が答えたか分からない形でのみ表示する

### ③ 提案
- 従業員画面: 記名/匿名を選んで自由記述の提案を投稿する
- 店長画面: 提案一覧をステータス（未対応/対応中/完了）付きで管理・更新する

## 認証・匿名性

- Flaskのセッション（`flask.session` + `secret_key`）でログイン状態を保持する
- 一般パスワード・管理者パスワードは`config.json`で管理する（POSと同様の方式）
- 匿名アンケート・匿名提案では、フォーム自体に名前選択欄を出さず、サーバー側でも
  `employee_id`を保存しない。アクセスログ・IPアドレスなど個人特定につながる情報は記録しない

## エラーハンドリング

- Supabase接続エラー時は「通信エラーが発生しました。時間をおいて再度お試しください」等、
  日本語のわかりやすいメッセージを表示する
- 入力必須項目の未入力はフォーム側でチェックし、送信前にエラー表示する
- 想定外の例外はログに日本語メッセージで記録し、画面には汎用エラーメッセージのみ表示する
  （スタックトレースは表示しない）

## テスト方針

- Flaskのテストクライアントで主要ルートのみ簡単な確認テストを用意する
  - ログイン成功/失敗
  - 目標採点の登録
  - 匿名アンケート回答で`employee_id`が保存されないこと
- それ以外は手動での動作確認手順をREADMEにまとめる
