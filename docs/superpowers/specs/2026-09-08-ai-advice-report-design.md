# 月次AI改善提案レポート 設計書

作成日: 2026-09-08

## 背景・目的

`売上管理\pos_system\dashboard.py`（POSデータ抽出ダッシュボード）には、既に「部門別分析レポート」
機能（小分類ごとの売上・荒利率・SKU数などを集計しExcel出力）がある。

これに加えて、月単位・店舗ごとに、売上データと部門別売上データから「利益率向上」「売上向上」の
ための改善提案を自動生成する機能を追加する。数値の抽出はルールベースで行い、その数値を根拠に
Claude API（`claude-opus-5`）が日本語の助言文を生成する。

## 全体フロー

1. サイドバーに「🤖 AI改善提案レポート」区画を追加する。**管理者（`is_admin`）のみ表示**する。
2. 日付モードが「月選択」のときのみ有効（前月比較の期間を一意に決めるため）。それ以外のモード
   では区画を表示せず、「月選択モードでご利用ください」の注意書きのみ表示する。
3. API利用料金が発生する旨の注意書き＋同意チェックボックスを表示し、チェックが入るまで
   実行ボタンを無効化する。
4. 実行ボタン押下で、サイドバーで選択中の店舗ごとに順番に処理する（進捗バー表示）。
   店舗ごとに:
   1. 当月・前月の店舗合計（売上・荒利・点数・客数）を取得する
   2. 当月・前月の部門別データ（既存`query_bumon_analysis`を再利用）を取得する
   3. ルールベースで数値サマリーを作成する（下記「数値抽出ロジック」参照）
   4. その数値サマリーをClaude APIに渡し、「■現状分析」「■改善施策」形式の助言文を生成する
   5. 1店舗の生成に失敗しても処理は止めず、その店舗だけエラー表示にして次へ進む
5. 結果は画面下部に店舗ごとの開閉パネル（`st.expander`）で表示し、生成文とあわせて当月/前月の
   主要数値の小さな表を表示する。
6. 全店舗分をまとめた`.docx`を「📥 Wordダウンロード」ボタンで提供する。

## 新規関数（`dashboard.py`に追加）

| 関数 | 役割 |
|---|---|
| `get_prev_month_range(start, end)` | 選択期間がちょうど1か月分であれば、その前月の(開始日, 終了日)を返す。それ以外は`None` |
| `get_store_totals(start, end, store_db)` | 指定期間・店舗の売上合計・荒利合計・点数合計・客数合計をSQLで集計する |
| `build_metrics_summary(store_label, period_label, cur_totals, prev_totals, cur_bumon, prev_bumon)` | 当月/前月の店舗合計と部門別データを突き合わせ、荒利率・売上の増減が大きい部門トップ3、全体の前月比増減率などを数値だけの日本語テキストにまとめる（AIへの入力材料） |
| `call_ai_advice(store_label, period_label, metrics_text)` | Claude API (`claude-opus-5`) を呼び出し、助言文を生成して返す。失敗時は例外を上位に投げず、呼び出し元でエラー文言に変換する |
| `make_advice_docx(results, period_label)` | 店舗ごとの助言文をまとめた`.docx`をバイト列で返す（`make_bumon_excel`と同様の構成） |
| `get_anthropic_key()` | `get_db_url()`と同じパターンで、Streamlit Secrets優先→なければ`config.json`の`anthropic_api_key`を返す |

## 数値抽出ロジック（`build_metrics_summary`）

- 全体: 当月/前月の 売上・荒利・荒利率・客数・客単価 とその増減率
- 部門別（`small_cat_name`単位、`query_bumon_analysis`のカテゴリー・売上・荒利・荒利率を当月/前月で
  カテゴリー名をキーに突き合わせ）:
  - 荒利率が悪化した部門トップ3（前月比マイナス幅が大きい順）
  - 荒利率が改善した部門トップ3
  - 売上が減少した部門トップ3
  - 売上が増加した部門トップ3
- 前月に存在せず当月に新規発生した部門、当月に存在せず前月から消えた部門があれば、その旨も
  数値サマリーに含める
- 出力は数値と部門名のみの簡潔な日本語テキスト（AIへの入力に使うため、文章化はしない）

## AI呼び出し設計

- モデル: `claude-opus-5`
- `thinking: {"type": "adaptive"}` を指定
- システムプロンプト: 「あなたは駄菓子小売チェーンの経営コンサルタントです。与えられた実績数値
  だけを根拠に、日本語で店長向けの改善提案を書いてください。憶測や一般論だけの助言は避け、
  具体的な部門名・数値に基づいて指摘してください」
- ユーザーメッセージ: `build_metrics_summary()`が作った数値サマリーのテキスト
- 出力形式指示: 「■現状分析」（3〜4文）＋「■改善施策」（箇条書き3〜5個、それぞれ理由付き）
- `max_tokens`は1600程度（非ストリーミング）
- 例外処理: Claude APIのエラー系例外（レート制限・認証エラーなど）を捕捉し、`call_ai_advice`は
  「⚠️ 生成に失敗しました（理由）」という文字列を返す。呼び出し元はこれをそのまま結果表示に使う
  （エラーで処理全体を止めない）

## UI

- サイドバーの「⑤ 集計オプション」の下に、管理者のみ表示される区画を追加する
  - 注意書き＋同意チェックボックス「API利用料金が発生することに同意して実行」
  - 「🤖 AI改善提案レポート」ボタン（チェックボックスが入るまで無効）
  - 選択店舗数を事前に表示する（例:「選択中の5店舗を分析します」）
- 結果表示は既存の抽出結果・部門別分析と同じ位置づけで画面下部に追加する
  - 店舗ごとに`st.expander`（開閉パネル）
  - パネル内に生成文（`st.markdown`）＋当月/前月の主要数値を並べた小さな表
- ダウンロードボタン「📥 Wordダウンロード」で全店舗分の`.docx`を提供する

## 依存関係

- `requirements.txt`に`anthropic`と`python-docx`を追加する
- どちらも既存の`psycopg2`・`openpyxl`と同じtry/exceptインポートパターンでガードし、
  未インストールでも他機能（抽出・部門別分析）には影響しない。未インストール時は
  AI改善提案レポート区画に警告を表示するのみとする
- `config.json`に`anthropic_api_key`を追加する（Streamlit Cloud運用時はSecretsに設定し、
  `config.json`には設定しない運用も可）

## 安全対策のまとめ

- 管理者専用表示（`is_admin`が真のときのみ区画を表示）
- 月選択モード限定（前月比較の期間を一意にし、意図しない大量課金を防ぐ）
- 実行前の同意チェックボックス必須
- 店舗ごとにtry/exceptし、1店舗の失敗が全体を止めない

## テスト方針

- `build_metrics_summary`・`get_prev_month_range`はDB非依存のロジックなので、サンプルの
  DataFrame/dictを与えたユニットテストで検証する（トップ3抽出・前月比計算・月範囲判定の
  境界値）
- `call_ai_advice`・`make_advice_docx`はAPI呼び出し部分をモック化し、フォーマット崩れがないかを
  確認する
- 実機確認は`streamlit run dashboard.py`をローカルで起動し、管理者ログイン→月選択→店舗選択→
  実行→画面表示・Wordダウンロードの一連の流れを目視確認する
